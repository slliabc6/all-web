# all-web 核心原则：模板复用优先

生效日期：2026-10-14。来源：用户明确决定；参考 [Astro 模块化建站文章](https://www.10100.com/article/141320492)。

## 第一优先级

模板复用是批量建站的基础，也是本项目最重要的长期资产。每个品牌网站都是模板、主题配置、品牌数据和素材组合出来的实例，不能每次重新生成一个孤立页面。

本决定覆盖此前“先把单页视觉做完，再顺便考虑模板”的执行优先级。保留此前复盘中的成本控制、真实验收和准确报告要求；减少重复审查不等于取消模块化基础。

## 必须积累的五层资产

1. 全站规则：主题颜色、字体、间距、响应式规则、导航结构、URL 与 SEO 默认规则。
2. 通用组件：导航、页脚、首屏、产品卡片、画廊、FAQ、询盘入口及交互状态。
3. 页面模板：主页、产品列表、产品详情、关于我们、联系页、博客等；按实际需要建设，不为凑齐目录实现无关功能。
4. 内容与配置：品牌名、产品资料、美元价格、联系方式、图片路径和页面组合独立于模板；切换品牌优先换数据与主题。
5. 智能体调用规范：模板 ID、版本、输入字段、示例、运行/导出方法和验证范围，让没有聊天上下文的智能体也能使用。

组件修改后，引用该版本的站点在重新构建后获得变更；已部署成品不会凭空更新。记录版本，避免修改共用组件意外影响所有品牌。

## 技术方向与交付方式

默认以 Astro 静态模板组织正式建站源代码，必要交互可使用 React；不为简单展示强加 React 运行时。已有可复用实现先检查、再提炼，不无故推倒重建。

模板源代码与最终预览包分别交付。用户要求直接查看时，提供经 file:// 实测可用的 index.html 与本地 assets，或独立离线预览导出；不能只给 localhost 地址，也不能把文件预览限制当成否定模块化架构的理由。

当前任务仅确立并同步原则，不代表上述模板、批量生成器、导出器或询盘后端均已实现。具体能力以实际文件和验证记录为准。

## 视觉与绘图资产

页面视觉是模板主题层，图片是可替换素材层。可以根据参考设计和真实产品资料，用 AI 绘图生成场景、主视觉、纹理和展示素材；无需等全部实拍完成才建设模板基础。

同时保存提示词、输入参考、生成图、适用模块与使用说明，使绘图方法也能复用。AI 图不能替代真实规格，不把生成的产品差异当成实物事实。

## 后续每个网站的最短工作流

查找已有模板 → 复用或补齐必要模块 → 填入品牌数据与主题 → 生成/替换视觉素材 → 导出网站及所需预览包 → 做一次针对性验收 → 登记新增复用资产。

首个实例与最小可复用模板一起实现，不先造庞大平台，也不事后无限期推迟模板提炼。优先证明同一模板能由不同品牌配置生成不同实例。

验收关注：共用布局是否集中维护、数据能否替换、调用说明能否复现、最终文件是否按承诺打开、关键交互是否正常。无关审批、机械多轮复审和重复构建不属于模板地基。

## GitHub、Notion 与本地分工

- GitHub：模板源代码、组件、配置结构、调用规范和版本记录，是技术事实来源。
- Notion：核心原则、资产导航、使用说明、决策与状态，链接 GitHub 的实际文件，不维护漂移的第二套代码。
- 本地：原始图片、视频、大文件及预览包；按负责人习惯手动备份。
- 同步完成必须分别取得 GitHub 提交及 Notion 保存证据，不把本地修改说成云端已保存。本次同步不自动建立持续同步任务。

部署平台不是模板资产本身。Hostinger、Cloudflare 等在需要部署时选用，不由参考文章自动触发迁移。mailto、后台接收和邮箱实际收到仍分别说明。
