# Cupsky 模板提炼设计

## 意图

把用户提供的 Cupsky 静态商店从“一套写死的页面”提炼为现有 Astro 静态购物站中的可复用主题、首页配方、组件变体和示例配置。模板面向餐饮包装、耗材、批发用品等目录型商店；品牌、商品、图片和联系方式必须可以独立替换。

## 目标

- 保留 Cupsky 最有辨识度的结构：深青公告栏、弧顶拼贴首屏、三组用途分类、紧凑商品网格、服务故事和批发横幅。
- 复用现有导航、搜索、购物车、商品详情和询盘逻辑，不复制 40 多个重复 HTML。
- 新增一套公开安全的虚构示例品牌和自制包装用品 SVG，证明模板可构建、可离线打开。
- 输出一份普通静态目录，以 `index.html` 为入口，并把展开后的模板成品和说明保存到“小李”Google Drive。
- 记录 Cupsky 原站与模板模块的映射，便于后续用真实品牌数据替换。

## 非目标

- 不接入支付、订单、登录、库存、运费或真实结账。
- 不复制原站的 checkout 提交逻辑；购物车仍以复制询盘清单和打开邮件草稿结束。
- 不把桌面 Cupsky 原始商品图、公司资料或整站源码提交到公开 Git；其公开权利未独立核实。
- 不为此次提炼新增框架、运行时依赖或部署平台适配。

## 方案比较

1. **原样整理现有 HTML**：速度快，但品牌、数据和重复页面仍耦合，无法批量复用，不选。
2. **新建第二套独立模板工程**：可忠实复刻，但会重复购物车、搜索和构建逻辑，不选。
3. **在现有 Astro 模板中新增主题与配方（采用）**：复用既有页面和交互，只增加包装行业需要的视觉变体、内容配置和示例数据，最符合模板优先原则。

## 结构

- 主题 ID：`packaging`，CSS 位于 `src/styles/themes/packaging.css`。
- 配方 ID：`packaging-catalog`，组合 `packaging-collage`、`use-case-cards`、`counter-grid`、`service-story` 和 `planning-banner` 变体。
- 示例站：`sites/轻快包装用品/`，采用虚构品牌 `Common Table Supply`，英文为默认语言，混合销售模式。
- 示例商品库：`data/catalogs/packaging-essentials/`，包含 8 件虚构商品和仓库自制 SVG。
- Cupsky 参考记录：`references/cupsky-template-source/README.md`，只记录本地来源、观察结果、模块映射和权利边界，不复制原始文件。

## 视觉系统

- 颜色：Deep Teal `#173d47`、Paper `#f7f5ee`、Signal Orange `#ef683a`、Mist `#d9e9e9`、Sage `#dce3d1`、White `#fffefa`。
- 字体：沿用本地 Manrope 作为界面字体，Newsreader 仅用于句中有语义的编辑式强调；不依赖在线字体。
- 布局：左侧短文案、右侧弧顶商品拼贴是唯一主要视觉动作；下方保持密集但清晰的目录节奏。
- 对齐：标题、正文和商品信息左对齐；分类卡与批发横幅用明确的网格，不用通用圆角卡片堆叠。
- 差异化原则：把包装产品本身当作图形语言；数字只用于真实的用途分组，不作为装饰性章节编号。

## 数据和交互

- 品牌和站点配置继续通过现有 JSON schema 加载。
- 商品沿用固定价、阶梯价和仅询价三种模式；示例同时覆盖零售小包和批发 MOQ。
- 搜索、购物车和询盘只在浏览器运行；邮件按钮只打开草稿，不声称已经提交或收件。
- 所有静态资源使用相对路径，最终成品必须通过 `file://` 打开。

## 验收

- schema 和配方测试覆盖新主题及所有新变体。
- 四个示例站批量构建成功，静态引用检查通过。
- 包装用品示例站的首页、商品详情、搜索和购物车在桌面与手机浏览器中通过。
- `file://` 打开最终 `index.html` 时无外部请求、无资源错误，页面图片和本地字体正常显示。
- 云盘保存普通文件夹，不以 ZIP 作为参考入口。
