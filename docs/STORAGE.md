# 存储与备份

## 存储分工

当前本机仓库位置：`D:\all-web`。大文件与私人素材放 `D:\all-web\local-only`，其中 inbox 为待整理区，brands 为品牌原件，references 为参考资料，exports 为导出包，backup-records 为手动备份记录。其他机器可以选择不同根目录，索引尽量使用相对路径。

- Git：文档、结构化数据、代码、适量且获准公开的网页图片/截图。
- local-only/：高清原件、视频、设计源文件、下载包、私有资料；已被 .gitignore 忽略。
- 云盘：“小李”Google Drive（用户说明容量 5 TB）用于模板和后续数字资产备份；2026-10-20 已创建 `网页模板资产库` 并上传首批模板资产，仓库没有自动同步。
- 正式网站：构建时拷贝已选定的网页素材，不使用网盘分享页或 GitHub 页面作为图片 CDN。

初始化仓库为 public。提交公司原图前确认可公开；不自动修改仓库可见性。
建议单文件超过 10 MB 先留本地并登记位置；这是本项目约定，不是 GitHub 硬限制。需要大文件版本管理时再讨论 Git LFS，目前未配置。
本地目录可能在不同机器上不存在，智能体必须说明缺失，不假装可以取得原件。

## 命名

示例：brands/example-brand/assets/web/MJ001_rose_detail_01.webp。
保持原件 original 与网站衍生图 web 分离。品牌、产品、素材各有稳定 ID；同一素材不靠反复改文件名表示版本。

## 备份

每周及每次交付后，手动备份本地原件、未提交资料和必要交付包。
备份文件使用日期，至少保留上一版，并下载/解压抽查。
GitHub 只备份已提交并推送的内容；local-only 和忽略文件不会上传。
在本地备份日志记录日期、范围、云盘位置、恢复抽查结果；涉及私密路径或链接时不提交公开仓库。
同一块硬盘上的另一个文件夹不算异地备份。

## 发布检查

检查来源和授权、敏感信息、真实客户资料、密钥及 Git 暂存区。
.gitignore 不是安全扫描器，也不能隐藏已经被 Git 跟踪的文件。
不自动添加全仓库开源许可证；每项素材/代码分别记录来源和使用范围。
